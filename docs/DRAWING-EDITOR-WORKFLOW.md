# Form and Luma drawing workflow

Both editors use a tool strip, central canvas, contextual properties, reversible gestures and local native projects. Form's sketch is measured source geometry for modeling; Luma's canvas retains pixel, vector, mask and layer tools. Their tools keep those domain meanings.

Shared implementation: pointer routing, coalesced sample collection with terminal-event fallback, frame coalescing, affine transforms and cursor cue primitives. `B` selects primary drawing and `V` selects/moves; Form adds `N` Pencil, `L` line, `R` rectangle and `C` circle. Luma retains its established contextual shortcuts (including vector Pen and image eraser/crop). Both offer Space-drag and middle-button pan, modifier/wheel zoom, Undo/Redo, cancel and native text/input fallbacks. Tap Space opens tool features. Mobile uses visible tool and navigation controls rather than keyboard-only gestures.

Form stores live vector samples outside React and draws admitted new segments on a passive overlay once per frame. Release retains the terminal coordinate and commits editable geometry once. Pointer loss/cancellation discards the in-progress gesture; foreign pointers cannot finish it. Off/Low/Standard smoothing is explicit, and clean-shape suggestions are optional/reversible. The iterative simplifier preserves the prior algorithm's output while avoiding recursive slices and repeated chord calculations. A stroke is limited to 65,536 admitted samples and fails explicitly at the limit.

Luma retains its existing incremental tiled brush engine, pressure/tilt behavior, touch navigation arbitration and adjustable stabilizer. Shared sampling also protects the dispatch endpoint and avoids repeated layout reads for retouch packets. Full preview quality now waits until an active brush transaction finishes or cancels, avoiding mid-stroke idle-quality oscillation. Saved pixels, geometry and exports are unchanged by preview quality.

Glyph was inspected as a resource: its bounded live point/pressure buffers, direct path authoring and font-space transforms reinforce the vector editor approach. Glyph font fitting/kerning code was not copied into an image or CAD engine; its prior isolated branch remains separate.

Responsive validation covers 390×844 phone and 820×1180 tablet layouts plus desktop. Form retains 44 px main toolbar/status actions and a separate properties region; Luma retains its phone tool families, touch-draw control and sheet panels. Existing orientation, viewport and touch arbitration tests are included. Browser input is emulated; physical pen/touch, palm rejection, 120 Hz displays, field INP and pen-to-display latency remain unqualified.

Performance evidence is scoped, not a “state of the art” certification. The reproducible Node benchmark records exact-output simplification at 1,000/10,000 points and a 24,000-sample admission burst. Local browser smoke observations exposed long frame stalls in development builds, particularly the six-layer 2200×1467 CPU photo stack. The live stroke and quality-timer fixes address identified causes; sustained high-density browser/hardware testing and further heavy-document compositor profiling remain necessary. The local-only `?drawingDiagnostics=1` option records actual canvas-gesture frame distributions without transmitting telemetry. It is available only on 127.0.0.1.
