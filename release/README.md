# Release Candidate gates

The gates are executable and deliberately stricter than the product UI.

- `npm run rc0:check` — type safety, the complete engine suite, desktop production build, sparse selections/masks, bounded memory, recovery, and destructive-failure tests.
- `npm run rc1:check` — RC0 plus at least 50 approved real PSD/PSB/RAW workflows with zero unexplained failures.
- `npm run rc2:check` — RC1 plus updater configuration and evidence for signed updates, notarization, remote crash collection, and clean-machine installation.
- `npm run release:status` — reports all gates without changing the exit code.

RC2 evidence files live under `artifacts/` and are intentionally generated by the release process, not hand-authored into source control:

- `notarization-report.json`: `{ "status": "Accepted", "bundleId": "app.luma.studio", "gatekeeperAccepted": true }`
- `updater-report.json`: `{ "signatureVerified": true, "previousVersionUpgrade": true, "interruptedUpdateRecovered": true }`
- `crash-reporting-report.json`: `{ "remoteCrashReceived": true, "symbolsResolved": true, "sensitiveDataScrubbed": true }`
- `clean-install-report.json`: `{ "withoutDevEnvironment": true, "machines": 2, "fileAssociations": true }`

These files are attestations from actual build/test jobs. Their presence does not replace logs or release artifacts; the JSON is the small machine-readable summary that makes the gate deterministic.
